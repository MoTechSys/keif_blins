# دليل الوكيل — كيف تعمل على هذا المشروع بالدقة التي يطلبها المستخدم

هذا الملف يصف **طريقة العمل** لا الكود. الكود موصوف في `README.md`، والتاريخ والقرارات في `CHANGELOG.md`.

## 1. المستخدم وما يتوقعه

- يخاطبك بالعربية ويتوقع الرد **بالعربية** فقط، مباشرًا بلا حشو.
- تعبيره المتكرر: «اشتغل بدقة»، «لا داعي أعيد كلامي»، «تحقق بدقة». يعني: لا تسأله عما يمكنك التحقق منه بنفسك، ولا تُسلّم شيئًا لم تره بعينك.
- يريد **صورًا** للمخرجات مع كل تسليم يمس المستندات، ويرفض التنسيق الذي لا يقنعه (حدث مع أول تصميم للكشف التفصيلي — أُعيد من الصفر).
- يهتم بـ: الحجم صغير، لا انهيار، كل شيء موثّق ومرفوع على GitHub بعد كل خطوة.

## 2. حلقة العمل الإلزامية لأي تغيير

```
1. flutter analyze                 → 0 issues
2. flutter test                    → كل الاختبارات ناجحة (لا تُضعف اختبارًا كي يمر)
3. إن مسّ التغيير PDF: صيّر وافحص بصريًا (§3)، أصلح، أعد التصيير
4. حدّث CHANGELOG.md تحت قسم الإصدار الحالي: ماذا تغيّر + لماذا (السبب الحقيقي، لا الظاهري)
5. حدّث docs/renders/ إن تغيّر شكل مستند
6. git add -A && git commit -m "<رسالة عربية دقيقة>" && git push origin main
7. الرد للمستخدم: ما تم بالضبط + روابط الصور + ما اكتُشف وأُصلح أثناء العمل
```

الدفع بعد **كل** خطوة منطقية، لا في نهاية الجلسة.

## 3. التحقق البصري لملفات PDF (الطريقة المعتمدة)

الاختبارات تكتب المستندات في `build/test_pdfs/` (invoice, quotation, statement, statement_period, statement_detailed, statement_detailed_long, receipt, receipt_account, stress_*). صيّرها بـ pymupdf وافحصها بأداة قراءة الصور:

```python
import pymupdf as f
from PIL import Image
d = f.open('build/test_pdfs/statement_detailed.pdf')
for i, p in enumerate(d):
    p.get_pixmap(dpi=110).save(f'/tmp/p{i+1}.png')     # صفحة صفحة للفحص الدقيق
# أو صفّ الصفحات جنبًا إلى جنب بـ PIL لنظرة عامة (dpi 70)
```

افحص تحديدًا: التفاف العناوين على سطرين في أعمدة ضيقة، انفصال الإجماليات عن جدولها بين صفحتين، اتجاه الأرقام اللاتينية، ظهور أعمدة/صفوف لا ينبغي أن تظهر (ضريبة/خصم غير مفعّلين).

**قاعدة:** لا تصف المستخدم شكل مستند لم تنظر إليه في هذه الجلسة.

## 4. خصوصيات مكتبة pdf المعدّلة (`third_party/pdf`)

- `pw.Table` لا يفهم RTL → استخدم `officialTable()` (يعكس الخلايا والأعرض). القيم اللاتينية تحتاج `textDirection: ltr`.
- `pw.Row` في RTL يضع أول عنصر **يمينًا**؛ `pw.Spacer()` أولًا يلصق ما بعده يسارًا.
- `pw.Column` العمودي **ينقسم** بين الصفحات (canSpan). لمنع الانقسام: `pw.Inseparable(child: ...)`.
- **خطر انهيار:** `Inseparable` أطول من صفحة كاملة يرمي `Widget won't fit into the page` ويُسقط التوليد. لذلك الكشف التفصيلي يقدّر ارتفاع البطاقة بالنقاط ويحوّل الكتل الطويلة إلى جداول قابلة للانقسام مع `TableRow(repeat: true)` للرأس. أي كتلة جديدة «لا تنقسم» يجب أن تُثبت أنها محدودة الارتفاع، وأن تُضاف حالة ضغط لها في `test/pdf_stress_test.dart`.
- `KEIF_PATCH.md` يشرح تعديل مسافات RTL في `text.dart`. لا تُحدّث المكتبة من pub.

## 5. معايير الحجم

- لا تُضِف حزمة إلا إن استُخدمت فعلًا (تحقّق بـ `grep -r "package:x" lib/`). أُزيلت `intl` لهذا السبب.
- الصور: أكبر عرض معروض × 3 هو الحد الأقصى المعقول للبكسلات (أيقونات الواجهة 160px لعرض 46dp).
- لا ترفع ثنائيات (APK/بناء ويب) إلى الفرع؛ مكانها **GitHub Releases** فقط. أُزيل مجلد `releases/` (52 م.ب) لهذا السبب.
- معاينات `docs/` بصيغة JPEG مضغوطة (≈ 60–200 ك.ب للصورة).
- حزمة arm64 ≈ 10.9 م.ب هي الحد العملي لتطبيق Flutter؛ 9 منها محرك Flutter وكود Dart المترجم.

## 6. الإصدار والنشر

1. `pubspec.yaml` → `version: X.Y.Z+N`، وحدّث `SettingsHub.version` في `settings_screen.dart`.
2. CHANGELOG: حوّل «غير منشور» إلى `## [X.Y.Z+N] — التاريخ`.
3. `flutter build apk --release --split-per-abi` (+ الشاملة إن لزم). تحقق: `aapt dump badging` (versionCode/Name) و`apksigner verify`.
4. وسم `vX.Y.Z` + إصدار GitHub (عبر REST API؛ `gh` غير مثبت) مع ملاحظات عربية وجدول «أي ملف أُنزّل» وSHA-256 لكل ملف. أعد تحميل الملف من GitHub وقارن الـ SHA.
5. مفاتيح التوقيع في `android/key.properties` و`android/release-key.jks` — **غير مرفوعة** (مُتجاهلة في git) ولا تُرفع أبدًا.

## 7. مواضع يسهل الخطأ فيها

- `buildStatement` هو مصدر الحقيقة لأرقام الكشف؛ أي مجموع يُعرض في الكشف التفصيلي يجب أن يساويه (هناك `assert` داخلي يفحص ذلك).
- الدفعات خارج الفترة تظهر في بطاقة الفاتورة (حالتها الفعلية) لكن **لا** تدخل ملخص الفترة.
- المسودات وعروض الأسعار لا تدخل الدفتر (`countsInLedger`).
- `store.payments`/`store.docs` تستثني المحذوفات (السلة منفصلة)؛ لا تُعد تصفية `isDeleted` إلا للمدخلات الخارجية.
- التنبيهات `print` ممنوعة (استخدم `debugPrint`)، و`withOpacity` مهجورة (استخدم `withValues(alpha:)`).
